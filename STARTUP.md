# VAPT Platform — Fixed Build

This is the **fully fixed** build of the multi-agent VAPT platform. All 12
original backend bugs + 6 runtime bugs discovered during the live scan test
have been resolved. The platform was validated end-to-end against
`scanme.nmap.org` (Nmap's official scan-friendly target) — 3 findings produced,
all 4 report formats generated.

## What was fixed

### Installation blockers
- **Frontend `npm install` 404**: `@radix-ui/react-badge` doesn't exist on npm.
  Stripped `package.json` to only the deps actually imported (next, react,
  react-dom, tailwind). The entire UI is hand-rolled Tailwind — no
  shadcn/radix/prisma/recharts needed.
- **Backend `requirements.txt`**: removed deprecated/broken packages
  (asyncio-redis, aioredis, asyncpg, psycopg2, langchain, pdfkit, weasyprint).
- **Backend `Dockerfile`**: fixed malformed uvicorn factory string
  (`web.app:create_app:app --factory` → `web.app:create_app --factory`),
  removed `--reload` from production, removed wrong `httpx-toolkit` pip install.
- **Frontend `Dockerfile`**: proper multi-stage build with standalone output.
- **`docker-compose.yml`**: correct env-var pass-through, healthcheck, shared
  volume for Docker-tool input files.

### Critical backend bugs
1. `web/app.py` — `@property` inside `create_app()` crashed every endpoint.
   Replaced with explicit `get_manager(app)` getter functions.
2. `services/scan_manager.py` — hardcoded absolute path; fragile scope parsing.
3. `agents/exploit.py` — missing `ScanResult` import (NameError at runtime).
4. `tools/runner.py` — conflicting `--network` + `--net=host`; host temp
   files invisible to Docker containers. New shared-volume system.
5. `core/orchestrator.py` — never passed `recon_data`/`enum_data`/`scan_result`
   between agents. New `_phase_context` store + `_build_task_parameters`.
6. `core/orchestrator.py` — async finding callbacks never awaited.
7. `core/config.py` — `ToolConfig` silently dropped `ports`, `template_tags`,
   `wordlist`, `level`, `risk`. New `settings` dict preserves them.

### Runtime bugs discovered during live scan
8. `core/orchestrator.py` — parallel-phase check fired BEFORE the current
   phase's agent ran, so `enum` was skipped entirely. Now runs current phase
   first, then looks ahead.
9. `core/orchestrator.py` — `_advance_from_phase` picked `fuzzing` over
   `vuln_scanning` (alphabetical sort). Now uses canonical pipeline order
   with profile-aware filtering.
10. `core/orchestrator.py` — partial parallel groups (e.g. va_only has
    `vuln_scanner` but not `fuzzer`) caused `vuln_scanner` to be skipped.
    Now runs in-profile members sequentially.
11. `agents/vuln_scanner.py` — `_run_custom_checks` used sync `httpx.get`
    inside an async agent, blocking the event loop. Converted to
    `httpx.AsyncClient`.
12. `agents/recon.py` — no fallback when all probes failed → 0 live URLs →
    downstream agents no-op'd. Now seeds `live_urls` with the primary target
    and emits an informational recon-summary finding.
13. `agents/reporter.py` — "Generated by AI" badge shown even when LLM call
    failed and template fallback was used. Now tracks actual LLM success.

### Feature: LLM-driven, NVD-verified CVE/CWE (no hardcoding, no hallucination)
New `tools/cve_resolver.py`:
- **LLM proposes** candidate CVE/CWE from concrete evidence (headers, tool
  output, tech stack) — explicitly instructed not to guess.
- **NVD verifies** every proposal: PUBLISHED → keep + attach official CVSS;
  REJECTED/NOT_FOUND → **dropped** (anti-hallucination guard); UNREACHABLE →
  kept but flagged `cve-unverified`.
- **CWE** validated against `CWE-NNN` format.
- Removed the hardcoded `vuln_versions` dict from `intel.py`.
- Reporter executive summary + per-finding remediation now LLM-generated
  (with deterministic template fallback).

Verified with real NVD calls:
- `CVE-2021-41773` → PUBLISHED, CVSS 9.8 attached ✓
- `CVE-9999-99999` (fake) → NOT_FOUND, **dropped** ✓

## Quick start

### With Docker (recommended)
```bash
docker-compose up -d --build
# Backend: http://localhost:8443/api/docs
# Frontend: http://localhost:3000
```

### Without Docker
```bash
# Backend
cd backend
pip install -r requirements.txt
python -m uvicorn web.app:create_app --factory --host 0.0.0.0 --port 8443

# Frontend
cd frontend
npm install
NEXT_PUBLIC_API_URL=http://localhost:8443 npm run dev
```

### Optional: enable LLM analysis
Set at least one provider key to enable AI-driven CVE/CWE proposal +
executive summary generation:
```bash
export OPENAI_API_KEY=sk-...        # or
export ANTHROPIC_API_KEY=sk-ant-... # or
export GEMINI_API_KEY=...           # or
export GROQ_API_KEY=...
```
Without keys, the platform still works — it just skips LLM enrichment and
uses the deterministic template fallback for the executive summary.

### Optional: enable Docker-tool isolation
The platform can run security tools (nuclei, nmap, ffuf, etc.) inside Docker
containers for isolation. If Docker is available, tools run containerized;
otherwise they fall back to direct execution (if the tool is installed
locally) or are skipped gracefully.

## Sample scan
`sample_reports/` contains a real scan run against `scanme.nmap.org`:
- `sample_report.html` — full interactive HTML report
- `sample_report.pdf` — printable PDF
- `sample_report.md` — Markdown

## API endpoints
| Method | Endpoint | Description |
|--------|----------|-------------|
| POST | `/api/scans/start` | Start scan (returns scan_id immediately) |
| GET | `/api/scans` | List all scans |
| GET | `/api/scans/{id}` | Full scan with agent status |
| GET | `/api/scans/{id}/findings` | Findings (filter by severity/agent/status) |
| GET | `/api/scans/{id}/agents` | Real-time agent status |
| POST | `/api/scans/{id}/stop` | Stop/cancel scan |
| GET | `/api/scans/{id}/report?format=html` | Download report |
| GET | `/api/modes` | Available scan modes |
| GET | `/api/stream` | SSE real-time events |
| GET | `/api/health` | Health + NVD stats |
| GET | `/api/tools/status` | Tool availability |
| GET | `/api/nvd/stats` | NVD verification stats |

## Scan modes
| Mode | Exploitation | Agents | Use case |
|------|-------------|--------|----------|
| `va_only` | No | recon, enum, vuln_scanner, reporter | Non-intrusive compliance assessment |
| `full_vapt` | Yes | All 7 agents | Complete penetration test |
| `web_app` | Yes | All 7 agents | Deep web app testing |
| `api` | Yes | All 7 agents | API security |
| `cloud` | No | recon, cloud, vuln_scanner, intel, reporter | Cloud misconfigs |
| `iot_cctv` | Yes | recon, iot, vuln_scanner, exploit, reporter | IoT/CCTV devices |
